# 资源市场生产就绪目标清单

本文把“将资源市场做到可安全上线并能持续运营”的总目标拆成可逐个交给模型执行的小目标。每个目标均可单独复制；执行时仍须先检查当前源码和工作区，不能仅凭本文件或历史文档假定状态未变化。

更新时间：2026-09-23

## 总目标与完成定义

总目标：在不破坏既有买家、卖家、运营、财务资金边界的前提下，完成资源市场业务链路、拒付运营、资金异常恢复、真实支付和存储设施验收、当前源码回归、部署及回滚验证；提供可审查的代码、测试、运行证据和准确文档。不得把“编译通过”“局部专项通过”“模拟 Provider 通过”或“页面显示成功”描述为生产就绪。

总体验收必须同时具备：

- 当前源码的分层自动化验证通过，或剩余失败已定位、隔离并形成有证据的阻塞说明；支付 Race 全包超时及 `go test ./...` 失败不能被旧快照结果替代。
- 买家发布/购买/交付/退款和卖家销售/结算/提现/银行结果/拒付/来源返还等关键资金路径均有可重复的隔离集成验证。
- Stripe、Waffo、银行、对象存储、媒体扫描、SMTP、worker、多实例、告警、容量、备份和恢复按实际启用能力完成对应环境验收；未配置的 Provider 能力保持 fail-closed。
- 迁移、发布顺序、回滚限制、运行配置、监控和人工处置手册经过审查；未验证的资金能力不开启。
- 文档、OpenAPI、前端、迁移矩阵和实际源码状态一致，所有结果标明源码版本、环境、命令和限制。

## 执行约定

1. 每次只执行一个目标。完成该目标的实现、测试和记录后停止，不自动开始下一目标，也不扩展成无边界重构。
2. 开始前读取本文件、相关业务文档、目标相关源码和 `git status --short`。工作区存在大量用户改动；保留所有非本目标改动，不覆盖、不回滚、不清理它们。
3. 目标完成时报告：改动文件、行为变化、实际运行的命令及结果、未覆盖风险、后续目标编号。失败时保留失败证据并说明是代码失败、测试环境失败还是外部服务未配置；不能通过删测试、放宽断言或跳过保护来换绿。
4. 对资金、权限、身份、幂等、审计、退款、权益和迁移行为，先写清不变量，再改实现。真实资金、生产数据库、外发邮件和生产部署不得以模拟验证代替；未获得该次明确操作授权时只准备可审查的验收步骤，不执行外部副作用。
5. 不声称“无漏洞”或“绝无 Bug”。以具体威胁面、回归证据和已知限制表述结果。
