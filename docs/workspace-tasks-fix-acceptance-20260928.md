## 迁移与兼容边界

新增迁移 `0180_task_delivery_kind`。部署本版服务前需按项目正常流程应用迁移；本轮只在隔离测试数据库验证，未迁移正在使用的开发库或生产库。

随后应用 `0181_task_delivery_asset_indexes`，为交付素材的常用所有者/时间范围查询增加部分索引。发布前可执行 [`deploy/task-marketplace-release-checks.sql`](../deploy/task-marketplace-release-checks.sql) 做只读预检；其中 mismatch count 应为 `0`。预检只验证数据库结构和合同完整性，不代替真实浏览器或支付验收。

内置分类按 code 回填（text 对应 document），旧自定义分类按原 icon 回填。旧分类缺少明确的交付类型，因此 icon 是兼容推断，不代表重新确认过历史业务约定。管理员可为未来任务显式配置 image/video/audio/document/prompt/workflow/mixed；分类变更不追溯更改已发布任务。省略新字段的旧分类更新保留现有配置，旧插入路径由数据库补默认值。

向下迁移会删除新配置及任务快照列。现在的 `0180` down migration 会在发现任务快照与当前分类映射不一致时主动拒绝降级，避免静默改写合同；如果确需回滚，必须先完成数据备份和显式的数据恢复方案。本轮往返测试验证原始兼容数据，不证明任意上线后数据可无损回滚。
