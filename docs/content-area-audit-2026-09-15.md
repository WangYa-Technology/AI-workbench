# 全站内容区域审查 · 2026-09-15

## 范围与方法

以本地开发服务器当前版本、演示数据为依据。浏览检查灵感库、作品详情、社区、帖子详情、资源市场和详情、任务广场和详情、创作者主页、搜索、资产和详情、已购内容、订单、任务工作台、计费、通知、账户、支持、创作、管理概览、政策页。使用创作者及管理员独立浏览器会话；不修改业务数据。

桌面基准 1308×901，移动布局抽查 390×844；采集内容文本、容器尺寸、截图并对照 Vue/CSS。主要内容容器未检测到横向溢出，但不等于所有内部表格、弹窗和长文本均已验收。订单、购买、支持主要看到空状态，后台仅检查概览；未覆盖全部管理子页、实际支付、完整错误状态和全站深色模式。初始阶段仅审查；随后已进入实施，进度和验证边界见文末。

## 原始审查记录（修复前）

以下为修复前基线；各项实施结果与验收证据见文末。

## 优先问题

### P1：作品详情的阅读和操作顺序

- `WorkPage.vue` 把整张作品放在信息前；移动端标题约在 y=683、主要操作约在 y=1295，首屏缺少作品身份和主要行动。
- `layout.css` 中 `.work-detail-media` 默认最小高度 620px，窄屏仍保留 420px；媒体展示和阅读信息互相争夺高度。
- 操作位于提示词、披露之后，没有复制提示词、展开长提示词或全尺寸查看入口。
- 返回链接固定 `/discover`，从筛选结果进入后返回会丢掉类别和搜索上下文。
- 做同款固定指向 `/create/image`，没有按媒体格式区分；当前列表页反而仅向图片提供该入口。
- 仅 onMounted 加载作品，同组件切换作品 ID 时缺少参数监听，存在旧内容保留风险（代码发现，尚未用第二件作品复现）。

建议：紧凑返回栏与标题摘要在前；桌面为限高预览和信息面板，手机先身份与操作再预览；提示词独立可复制区域，授权摘要常驻，完整披露可展开；保留来源筛选上下文，按格式定义复用入口。

### P1：状态标签与真实含义不一致

- 商品详情模板无条件展示“演示内容”，与是否演示商品无关。
- 商品授权条目全部使用 Check 图标，包括“禁止原样再分发或转售”，视觉符号无法区分允许、限制和义务。
- 通知类型下拉文本出现 `notifications.kinds.billing.wallet_topup_completed` 等原始翻译键。

建议：标签由业务字段决定；权限用明确的允许/禁止/需署名表达；补齐翻译并对未知类型提供可读回退。不得仅靠颜色表达许可。

### P1：加载范围仍未全站统一

社区 `loading/error/v-else` 包裹整个工具栏与分类内容，分类变更会把工具栏一起替换。任务广场已经将加载缩到右侧结果区，但相同约束尚未统一。

建议：页面框架、筛选、分类常驻，只更新结果；保留已有统计直到新响应返回；统一请求过期处理，并用延迟请求验证连续切换与失败重试。

### P2：原始代码和实现说明出现在产品界面

- 作品授权显示 `demo-display-only`；资产显示 `creator-owned-local-test` 和 `image`；创作者资源中显示 `hcai-personal-v1`。
- 搜索页展示“服务端统一排序”“排序策略 v1 · Balanced public relevance”；账户页包含 Provider、持久化目录、资源所有权检查等实现语言。

建议：面向用户提供授权名称、媒体类型和简短含义；技术版本和证据标识移到展开详情或管理员界面。用户创作的英文标题/描述无需强行翻译，系统文案与枚举应本地化。

### P2：创作者主页重复内容、滚动过长

顶部精选作品与下方作品集重复展示同一作品；演示数据仅 1 件作品、3 个资源，主内容滚动高度约 2056px。大图占据主要首屏，资源很靠后。

建议：保留紧凑身份区，作品/资源使用分区或标签切换；精选展示仅在内容数量足够时使用，避免重复相同作品。

### P2：商品详情的购买信息与内容身份脱节

标题在大预览下方，价格与结账面板先出现。支付不可用说明重复出现在价格下、按钮文案、按钮下。主图固定裁切会让作品授权用户看不到完整画面。

建议：顶部先产品名称、类型、作者；预览支持完整查看；购买栏保留价格、关键授权、一个短状态解释和一个短操作标签。

### P2：工作台密度与文案重复

资产卡重复安全状态、授权、演示来源；已购内容/订单/任务空状态又重复顶部跳转入口。计费页支付不可用提示在多个区域重复；钱包、订阅和趋势同时使用多层卡片，辅助文本大量低于 12px。通知的标题、摘要在 Hero、侧栏、内容头重复。

建议：每个层级只承担一种信息职责；主区正文以 13–14px 起，11–12px 留给辅助元数据；钱包/订阅分区明确；全局不可用提示只保留一次，局部控件保留禁用原因关联。

### P2：列表统计与分类能力不一致

灵感库统计是已加载数量，任务广场统计来自任务目录，其他页面使用当前列表值；相似的三块统计并不代表相同口径。灵感库已有分类数字，但社区/资源市场尚未向共用分类组件传入统计。

建议：区分全量、筛选结果、已加载数量，标签明确；类别计数统一由服务端在相同筛选维度统计，避免当前页计数冒充总量。

### P2：后台概览混合“查看”和“编辑”

管理概览首屏为 7 个统计卡片，紧接站点品牌、政策及页脚编辑表单；阅读概览与修改配置混在同一页面。卡片阴影和边框比前台内容更重。

建议：概览优先待处理事项和关键统计，站点配置独立到现有设置导航；降低装饰层级。后台表格不应机械套用前台作品卡布局。

## 补充：任务详情与社区帖子详情

再次浏览演示视频任务和关联作品帖子，使用创作者身份，检查 1308×901 和 390×844；以下把实测现象与代码风险区分记录。尚未实际提交提案、交付、评论或举报，也未覆盖所有任务生命周期。

### 任务详情

1. **P1，关键决策信息后置。** 手机端报酬区域约 y=1683，操作栏约 y=1664，跳转操作区的按钮约 y=1397。需阅读简报、规则、版权等内容后才看到金额和截止时间。应在标题下集中展示报酬、截止时间、类型、资金状态和参与条件，详细规则放其后。
2. **P1，资金状态表达不准确。** 当前“已资助报酬”直接展示 budgetCents，模板没有依照 funding 状态选择标题。预算与已确认资助金额应分开，不能让预算标签暗示支付已确认。
3. **P1，创作入口上下文未接通。** 任务详情和交付区固定跳 `/create/image?taskId=...`；当前 MultimodalCreationStudio 未读取 taskId 或传递 sourceTaskId。应按媒体类型选择能力，带入任务来源与简报，并明确创作不代表接单。
4. **P1，交付媒体渲染不区分格式。** task-deliveries 使用 img 直接显示所有 mediaUrl；视频、音频任务的交付记录存在失效图片风险。需按资产媒体类型使用统一预览器，展示版本、提交人、时间和审核结果。此项由代码确认，尚未以真实视频交付复现。
5. **P2，侧栏重复提示与滚动层级。** 同一支付不可用说明在报酬、操作前和结算区域重复三次；侧栏同时设置 min-height:700px、max-height 和 overflow-y:auto。长表单带来页面与侧栏双滚动，较矮屏幕上最小高度还可能超过可用高度。
6. **P2，信息块过大。** 356px 操作栏、52px 栏间距、大标题、彩色规则卡和装饰报酬插图同时争夺首屏。版权、披露、提案、交付、事件历史连续堆叠，缺少当前阶段指引。
7. **P2，返回入口重复且丢上下文。** “返回任务列表”与“找需求”都回同一列表，未保留原 type/status/view 条件。

建议结构：返回与标题 → 关键事实摘要 → 当前阶段及主操作 → 简报/交付标准/参与记录。桌面侧栏只保留简明操作摘要，复杂提案、交付和审核表单使用独立展开区；手机先展示关键事实，提供不遮挡正文的操作入口。权限继续由现有角色与任务状态控制，重要交付和许可条件不可默认隐藏。

### 社区帖子详情

1. **P2，阅读字号与互动区域偏小。** 正文 13px，作者 11px，时间及类别 10px，关联作品说明和入口 10px，评论时间 9px；对比新列表页标题与按钮，进入详情反而更难读。正文建议 15–16px、辅助信息 12px 起，互动点击区域统一。
2. **P2，信息布局不适应内容。** 关联作品占独立 264px 侧栏，但仅显示缩略图、标题和披露；短帖下大片留白。无关联作品时主栏变全宽，而正文仍限制 66ch，正文和评论区宽度缺少统一阅读尺度。
3. **P2，互动层级混杂。** 点赞、收藏、关注、举报均排在正文后；关注更适合作者信息，举报放更多菜单，正文下聚焦讨论互动。评论输入区标签与提交按钮都写“发表评论”，建议保留一个清晰标题并区分提交操作。
4. **P2，正文只能作为纯文本呈现。** 当前 p + pre-wrap 保留换行，但没有段落、列表、引用、代码或链接的结构化呈现。对于教程类帖子需明确支持的内容格式；若引入 Markdown，应复用已有安全渲染方案，不能直接放任 HTML。
5. **P1，关联作品复用仍固定图片入口。** 所有关联媒体都跳 `/create/image?sourceWorkId=...`，应与灵感库一致按类型控制入口。
6. **P2，返回社区丢筛选条件。** 返回链接固定 `/community`，不会恢复原分类/我的帖子视图。长讨论还需补评论锚点、加载更多失败反馈和登录后输入恢复的专门验收。

建议结构：返回 → 标题与作者 → 正文及关联作品 → 点赞/收藏/评论入口 → 评论列表与输入区。关联作品按内容形态使用正文内预览或轻量侧栏；帖子属于阅读与讨论页面，不应照搬交易页价格侧栏或插画 Hero。

## 更新后的实施顺序

1. 先统一作品/商品/资产详情的返回栏、媒体预览、信息区和操作区，并修复媒体入口、标签及翻译问题。
2. 统一加载范围、筛选上下文、统计口径和分类数字。
3. 收敛创作者主页、搜索和工作台的信息重复与字体层级。
4. 分离后台概览与配置，再逐页验收管理表格和弹窗。

## 统一约束与验收

- 沿用现有蓝色、圆角、紧凑控件和稳定分类栏；详情页无需强加列表页的插画 Hero。
- 图片预览限高且不裁掉作品，完整查看单独提供；手机首屏应出现标题、状态和主要操作。
- 框架、分类栏、筛选栏在加载中保持原节点；结果区反馈加载/空/错误，快速连续筛选以最后一次请求为准。
- 长标题、长提示词、无图、图片/视频/音频/文本、空结果和权限不足分别验证。
- 390/768/1308/1551px、浅色/深色、键盘操作和减少动态效果模式验收；内部滚动容器单独检测，不能只检测 document 宽度。
- 业务验收保留查看、复制、收藏、做同款、发布和原有授权限制，不为“简洁”隐藏影响使用决定的信息。
