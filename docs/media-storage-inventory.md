# 媒体存储只读盘点

更新日期：2026-09-21。适用源码基线：0135；没有新增数据库迁移。此工具用于资源市场、资产和生成文件的存储排查，不承担自动清理、恢复或生产验收。

## 1. 用途与边界

已有交付证据目录从订单和数据库出发，检查合同、快照等记录是否缺失。本工具从**当前存储对象**出发，对照同一个数据库只读快照，发现尚未找到引用的对象，以及已有清理证据但仍能枚举到的位置。两种检查互补。

工具不读取文件正文、不计算正文摘要、不写数据库、不运行迁移、不调用支付、邮件、扫描或清理服务。读取 S3 会产生真实的 ListObjectsV2 请求；本次验证仅使用回环模拟服务，未连接真实存储商。

结果不能作为删除授权。数据库快照与文件系统／S3 列表不是跨系统原子快照；并发上传、清理、恢复和外部写入都可能影响观察。`complete=true` 只表示本次约定范围的枚举、查询和报告写出成功，不表示所有历史文件已对账、所有文件内容健康或可以删除异常对象。

## 2. 枚举范围

| 后端 | 本次读取 | 明确不覆盖 |
| --- | --- | --- |
| `local_file` | `MEDIA_ROOT` 下的直接目录项，使用固定目录句柄与不跟随链接的元数据读取 | 子目录内容、其他挂载点／目录、离线备份；不打开符号链接或 FIFO |
| `s3` | 当前配置桶内、`MEDIA_S3_PREFIX/` 下的现存对象；空前缀表示整个配置桶 | 旧版本、删除标记、未完成分片、其他桶／前缀、其他账户和离线备份 |

S3 依赖普通桶按键排序的 ListObjectsV2 契约；不宣称支持目录桶。每页最多 100 项，XML 响应最多 4 MiB；拒绝重定向、越界前缀、无进展或重复分页、错误计数、异常键顺序及不完整响应。配置前缀以 `/` 结尾作为边界，`media/` 不包含 `media-other/`。

本地 `.media-*` 暂存文件按现存普通文件记录，不能仅凭名称认定可删除。目录、软链接、多硬链接、特殊文件和不支持的键会明确标记，不能当作普通可读媒体。枚举期间发现目录被替换、目录项无法读取或上下文被取消，本次失败。

本地目录身份检查只覆盖当前进程保存的身份，不证明跨重启挂载身份不变。数据库位置使用 `storage_backend + storage_key`，没有在每条旧证据中冻结桶和端点身份；同名键在不同历史存储配置中的归属仍须人工核对。

## 3. 如何执行

需要已配置的数据库与媒体环境变量，以及可读取全部相关记录的数据库账号。推荐使用专门的只读账号；工具自身使用 Repeatable Read、Read Only 事务，并设置 `row_security=off`，避免未来行级策略静默隐藏其他账号的引用。若账号不能绕过适用的行级策略，查询应失败，不产生完整报告。

先在仓库根目录编译：

```sh
go build -o /tmp/hcai-mediainventory ./cmd/mediainventory
```

选择一个已存在、受控的报告目录。报告路径必须是**新文件**；本地盘点要求报告目录在媒体根目录之外，也拒绝指向根目录内部的符号链接别名。

```sh
/tmp/hcai-mediainventory \
  -backend local_file \
  -output /secure/reports/media-local-20260921.jsonl \
  -max-entries 100000 \
  -timeout 10m
```

确认已配置正确 S3 桶、端点、前缀和读取身份后，使用相同命令并将 `-backend` 改为 `s3`，使用不同的报告文件名。该操作需要 `ListBucket` 读取权限，不需要写入／删除权限。S3 后端必须已在媒体配置中启用，工具不会自动换到其他存储。

| 参数 | 规则 |
| --- | --- |
| `-backend` | 必填，仅 `local_file` 或 `s3`；不隐式使用主后端 |
| `-output` | 必填，不覆盖已有普通文件、目录或符号链接 |
| `-max-entries` | 默认 100000，范围 1–1000000；超限失败，不把前 N 项当完整报告 |
| `-timeout` | 默认 10 分钟，范围 1 秒–30 分钟；数据库单次语句另限 15 秒 |

程序只读取环境配置，不自动加载 `.env`。没有运行 API／worker 的自动迁移副作用。数据库缺表或权限不足时，即使媒体目录为空，也不能成功生成“空盘点”。长快照可能增加数据库 MVCC 保留压力，应选择合适的执行时段和上限；超时后重新评估范围，不把不同快照的片段直接拼成一次完整盘点。

## 4. 报告格式

文件为 JSONL，权限为 `0600`，含私密对象位置，按运营证据保管。标准输出只有汇总计数，不输出对象名、账号资料或凭据；失败只输出阶段，不透出原始数据库连接或存储错误。退出码 0 表示报告已写出，1 表示执行／输出失败，2 表示参数错误。

1. 首行 `kind=inventory`：版本、后端范围、数据库事务时间、条目上限及限制说明。S3 保存桶、前缀和端点配置摘要；本地保存根目录路径。
2. 每个 `kind=object`：原始键的 Base64、键 SHA-256、条目类型、观察到的大小、分类、引用类别和清理证据类别。键摘要不是文件内容摘要。Base64 保留非 UTF-8 本地文件名，不是加密。
3. 末行 `kind=summary`：`complete=true` 及四类计数；四类计数之和等于 `entries`。有清理证据的对象归入异常类，同时保留找到的引用类别。

| 分类 | 解释 | 后续处理 |
| --- | --- | --- |
| `referenced` | 当前快照至少有一类引用，且没有本工具匹配的清理证据 | 根据具体订单、资产和保留规则继续核查；不等于内容完整或永久保留 |
| `unreferenced_in_snapshot` | 当前快照中没有匹配引用 | 核对并发写入、迁移、旧配置和备份来源；不得直接删除 |
| `present_with_cleanup_evidence` | 能枚举到该键，且已有移除／缺失证据 | 核对晚到写入、恢复或键重用，并保留原证据；不能仅据此断定同一份字节“复活” |
| `unsupported_entry` | 目录、链接、特殊文件或不支持的键 | 单独调查；本工具未遍历其内容，也未完成普通媒体引用核查 |

原始报告先流式写入同目录的私密临时文件，成功后使用不覆盖目标的原子链接发布。超限、取消、存储／数据库错误或目标被并发创建均不发布新的完整报告。普通错误会移除临时文件；进程崩溃可能遗留 `.media-inventory-*.jsonl.tmp`，这不构成完成证明。工具不承诺断电后的目录项持久性，报告仍需按正式证据保管流程备份。

## 5. 对照的数据库证据

| 引用类别 | 数据源 |
| --- | --- |
| `asset` | `assets.storage_backend/storage_key`，不按所有者或资产状态过滤 |
| `contract_source` | `product_order_media_sources`，统一覆盖冻结单文件与 ZIP 成交成员 |
| `snapshot_source` / `snapshot_target` | `product_delivery_snapshots` 原来源与交付位置，包括历史状态 |
| `repair_source` / `repair_target` | `product_delivery_repairs` 来源及修复目标，包括旧修订 |
| `upload_journal` / `generation_journal` | 上传及生成写入日志，包含待关联、已关联和已清理记录 |

清理异常另外匹配 `original_media_cleanup_receipts` 中的键摘要、快照／修复 `state=removed`、上传／生成日志的 `verified_absent_at`。它们不会因为另一个来源仍有引用而被隐藏。

已有 0042 迁移把上传／生成的旧本地位置写入显式存储字段；工具只使用这些正式字段及冻结合同来源，不从 `media_url`、标题或后缀猜测文件身份。缺少正式来源的历史数据仍属于证据缺口，不伪造迁移结果。查询按最多 100 个键批处理，保留一个数据库快照；不把所有桶对象或全部历史证据加载到内存。
