## 优先问题

1. **P1：资产卡片遗漏迁移。** WorkspacePage 的 asset-result-list / task-row asset-row 未添加 ui-catalog / ui-content-card；旧 task-row 基础规则已移除 padding、border、background 等声明，因此现有资产及收藏列表存在外观退化风险。应优先接入共享类并验证。
2. **P2：计费页未接入。** billing-account-overview、billing-filters 为独立实现，workspaceHero 的分支没有 billing，吸顶观察也无法识别其头部。应保留余额、用量和账本业务信息，以可配置标题/筛选变体接入，不能直接复制任务统计。
3. **P2：旧规则与共享规则并存。** layout.css 的 task-result-list.is-grid 和页面 scoped 的 market-catalog.is-grid / inspiration-catalog.is-grid 与 catalog.css 重复。当前依靠选择器优先级覆盖，后续容易再次出现尺寸不一致。
4. **P2：共享筛选仍依赖页面类。** ui-filter-bar 的规则直接列举 inspiration-filters、market-filters、task-filters、community-toolbar。新页面仅添加 ui-filter-bar 并不足以获得完整自适应布局。应抽取搜索槽、筛选槽和操作槽语义接口。
5. **P2：缺少统一接入测试。** 现有人工验证不能防止页面局部 CSS 重新覆盖公共规则，应增加共享组件行为测试及典型页面的计算尺寸/键盘回归。
6. **P3：普通返回栏重复。** 吸顶栏已统一，但四个详情页仍分别定义顶部返回栏的 40px 高度、16px 间距、字号和颜色，可抽取 DetailToolbar。
7. **P3：PageHero 仍有例外覆盖。** account-hero 的统计字体、notification-hero 的图片宽度仍留在 layout.css；应转为组件属性或明确的视觉变体。

## 建议执行顺序

先补资产遗漏；再抽取语义化 FilterBar、Catalog/Card 和 DetailToolbar 接口，迁移现有四目录并删除重复规则；随后迁移计费、通知筛选、创作者及搜索结果中适用的区域；最后补覆盖清单和自动化回归。保留支付确认、授权信息、后台表格、创作画布等业务差异。
